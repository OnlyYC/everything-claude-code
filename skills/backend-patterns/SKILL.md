# 后端架构模式

通用后端架构模式和设计原则，不依赖具体框架实现。

## 技能职责划分

| 技能 | 职责 | 内容范围 |
|------|------|---------|
| `backend-patterns` | **通用架构** | REST API 设计原则、分层架构理论、通用最佳实践 |
| `springboot-patterns` | **框架实现** | Spring Boot 特定注解、配置、WebFlux、R2DBC |

## REST API 设计原则

### 统一 API 结构

基于 RESTful 风格设计，使用资源导向的 URL。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/users | 获取列表 |
| GET | /api/users/{id} | 获取单个资源 |
| POST | /api/users | 创建资源 |
| PUT | /api/users/{id} | 全量更新 |
| PATCH | /api/users/{id} | 部分更新 |
| DELETE | /api/users/{id} | 删除资源 |

### 统一响应格式

```java
// 成功响应
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}

// 错误响应
{
  "code": 400,
  "message": "参数错误：姓名不能为空"
}
```

### 分页参数规范

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| page | int | 0 | 页码（从0开始） |
| size | int | 20 | 每页大小 |
| sort | string | - | 排序字段：字段名,asc/desc |

## 分层架构设计

### 三层架构原则

```
┌─────────────────────────────────────┐
│        Controller 层                  │  - 接口暴露、参数接收
├─────────────────────────────────────┤
│        Service 层                     │  - 业务逻辑编排
├─────────────────────────────────────┤
│        Repository 层                  │  - 数据访问
└─────────────────────────────────────┘
```

### 层级职责

| 层级 | 职责 | 禁止事项 |
|------|------|---------|
| Controller | 参数接收、响应封装、权限检查 | 业务逻辑、直接访问数据库 |
| Service | 业务逻辑编排、事务控制 | 直接访问 HTTP、数据库细节 |
| Repository | 数据访问、实体转换 | 业务逻辑 |

### 依赖方向

```
Controller → Service → Repository
    ↑           ↑          ↑
    └───────────┴──────────┘
       只能向下依赖，禁止反向
```

## 数据库优化原则

### 只查询需要的字段

```sql
-- 错误 - 查询所有字段
SELECT * FROM users WHERE status = 1;

-- 正确 - 只查询需要的字段
SELECT id, name, email FROM users WHERE status = 1;
```

### 避免 N+1 查询

```
错误模式：
1. 查询 10 条订单
2. 循环查询每条订单的用户信息（10 次查询）
总计：11 次查询

正确模式：
1. 查询 10 条订单
2. 批量查询所有相关用户（1 次查询）
总计：2 次查询
```

### 批量操作原则

```sql
-- 错误 - 循环单条插入
FOR EACH item IN items:
    INSERT INTO orders ...

-- 正确 - 批量插入
INSERT INTO orders (...) VALUES (...), (...), (...);
```

## 缓存策略

### 缓存模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| Cache-Aside | 先查缓存，未命中查数据库后写入缓存 | 读多写少 |
| Write-Through | 写入时同时更新缓存和数据库 | 一致性要求高 |
| Write-Behind | 先更新缓存，异步写入数据库 | 写入性能优先 |

### 缓存淘汰策略

| 策略 | 说明 |
|------|------|
| LRU | 最近最少使用 |
| LFU | 最少使用频率 |
| TTL | 时间到期过期 |

### 缓存穿透防护

```
问题：查询不存在的数据，缓存和数据库都没有，每次都查数据库
方案：
1. 布隆过滤器 - 快速判断是否存在
2. 缓存空值 - 将 null 结果也缓存
3. 请求限流 - 限制恶意请求频率
```

## 异常处理设计

### 异常分类

```
异常体系
├── 业务异常（BusinessException）
│   ├── 参数错误（400）
│   ├── 资源不存在（404）
│   └── 业务规则错误（如库存不足）
├── 系统异常（SystemException）
│   ├── 数据库异常
│   ├── 外部服务异常
│   └── 未知异常（500）
```

### 异常处理原则

1. **快速失败** - 参数校验不通过立即返回
2. **保留现场** - 不吞掉原始异常信息
3. **友好提示** - 用户看到的是友好提示，不是技术错误
4. **日志记录** - 所有异常必须记录日志

## 认证与授权设计

### 认证方式对比

| 方式 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| Session | 服务端存储会话 | 简单可靠 | 服务端有状态 |
| JWT | 无状态令牌 | 无状态、跨服务 | 令牌无法撤销 |
| OAuth2 | 第三方授权 | 标准化 | 复杂度高 |

### 授权模型

```
RBAC（基于角色）
用户 → 角色 → 权限

ABAC（基于属性）
用户 + 资源 + 环境 → 决策
```

## 限流策略

### 限流算法

| 算法 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 固定窗口 | 单位时间固定请求数 | 简单 | 边界突刺 |
| 滑动窗口 | 时间滑动窗口 | 平滑 | 实现复杂 |
| 令牌桶 | 恒定速率放入令牌 | 平滑突发 | 漏桶相反 |
| 漏桶 | 恒定速率处理请求 | 强制平滑 | 无法处理突发 |

### 限流维度

```
IP 限流 - 防止单个 IP 过度请求
用户限流 - 防止单个用户过度操作
接口限流 - 保护核心接口资源
```

## 异步处理设计

### 异步场景

| 场景 | 方案 |
|------|------|
| 发送通知 | 消息队列 / 异步方法 |
| 数据同步 | 定时任务 / 事件驱动 |
| 耗时计算 | 线程池 / 异步任务 |

### 事件驱动架构

```
事件发布
    ↓
事件总线 / 消息队列
    ↓
事件订阅者 1、2、3 ...
```

## 日志监控设计

### 日志级别规范

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| ERROR | 影响系统正常运行 | 数据库连接失败 |
| WARN | 不影响运行但需注意 | 缓存未命中 |
| INFO | 关键业务流程 | 订单创建成功 |
| DEBUG | 调试信息 | 查询参数详情 |

### 监控指标

```
业务指标
- 订单量、支付成功率
- 用户活跃度、响应时间

技术指标
- CPU、内存、磁盘使用率
- QPS、响应时间、错误率
```
